# Testing table mode

Table mode is experimental: gqlgen generates in it only when it is built with the
`gqlgen_table` build tag, such as with `go run -tags gqlgen_table github.com/99designs/gqlgen`.
See `docs/content/reference/table-mode.md`.

This test server generates its schemas in both modes into separate packages and checks that
both executors give the same response to every request. Its table packages are generated by
`go run -tags gqlgen_table` in their `go:generate` lines. Its tests that run the generator do
not build with `-race`, and generate in the exec mode that the test binary is built for, so run
both of these to check both modes:

```shell
go test ./codegen/testserver/tablemode/
go test -tags gqlgen_table ./codegen/testserver/tablemode/
```

The other test servers in `codegen/testserver` are committed in the default functions mode. CI
runs their tests against table mode too: `.github/workflows/check-table-mode` sets
`GOFLAGS=-tags=gqlgen_table`, generates them again with `go generate` and runs the same tests.
It rewrites the generated code in the working tree, so to run it locally, run it on a clean
checkout and restore the files afterwards with `git checkout -- .`. Tests of the test servers
should therefore use the exported API of the generated code, which both modes generate.

`check-table-mode` also regenerates the examples, the integration server and the test servers
of the federation plugin in table mode and runs their tests, the integration spec and the
federation spec against them.

The workflows of table mode are `.github/workflows/test-table.yaml`, `lint-table.yaml` and
`integration-table.yaml`, beside `test.yaml`, `lint.yaml` and `integration.yaml` of the default
mode.
